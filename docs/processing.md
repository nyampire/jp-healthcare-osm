# 変換処理の設計と根拠

各判断の根拠を実データの数値とともに残します。元データ側の性質は
[data.md](data.md) を参照してください。

## 通底する方針

1. **元データの列は書き換えず、変換後の値は別列として持つ。** 判断を覆したくなったときに
   戻せることと、第三者が対比して検証できることを優先します。
2. **判断を含む対応付けはスクリプトに埋め込まず `mapping/` のCSVに外出しする。**
   医学的判断や語彙の当てはめはレビューして直せる形である必要があります。
3. **除外・保留した行は理由とともに全件を一覧に残す。** 除外して終わりにしません。
4. **誤った値を出すより出力しない。** OSMでは値を書かないコストは低い一方、誤った
   休診情報を書くと利用者が来院できなくなります。
5. **判定基準は他行との比較ではなく絶対的な基準で行う。** 理由が一意に定まり、除外リスト
   から第三者が検証できるためです。imports ML で説明・レビューされる以上、説明可能性を
   精度差より優先します。

方針5については経緯があります。当初は中央値・最頻値による外れ値検出を実装しましたが、
基準にした中央値そのものが偏っている施設で正常値を誤検出しました（夜間コマは母数が
少なく、当直枠の `00:00-08:30` が中央値になるため、正当な夜間診療 `19:30-22:30` が
外れ値と判定された）。絶対基準に切り替えた結果、除外は実データの0.45%まで減り、
最終出力が変わる施設は0.6%にとどまりました。

## opening_hours

### 組み立て

診療科・診療時間票は1施設につき「診療科 × 時間帯」の複数行を持ちますが、OSMの
`opening_hours` はノードに1つしか持てません。そこで曜日ごとに全診療科の区間を
和集合して畳みます。

そのうえで施設票の例外ルールを後ろに重ねます。**`opening_hours` は後ろのルールが前を
上書きする**ため、順序が意味を持ちます。

```
基本時間 → 定期週の休み → 祝日 → 特定日の休み → 日付にできない期間のコメント

Mo,Tu,We,Th,Fr 09:00-12:00,13:30-17:00; Sa 09:00-12:00;
  Sa[2,4] off; PH off; Dec 30-Jan 03 off || off "GWは休診"
```

### 除外の基準

和集合は「一番早い開始〜一番遅い終了」を採るため、1行の誤入力が施設全体の値を汚染します。
これを防ぐため、外来として明らかに成立しない区間を除外してから畳みます。

| 分類 | 基準 | 件数 |
|---|---|---:|
| `null_placeholder` | 開始と終了が同一 | 4,473 |
| `too_early` | 開始が06:00より前 | 2,413 |
| `too_late` | 終了が23:00より後 | 583 |
| `overnight_implausible` | 日跨ぎとしても18時間超 | 461 |
| `sentinel_24h` | `00:00-23:59` | 201 |

全業態で8,131区間、対象の0.5%程度です。実データを落とした分はさらに少なく、
`null_placeholder` を除けば3,658件です。

実際の是正例:

```
市立札幌病院  除外前: Mo,We,Th,Fr 08:45-17:15; Tu 00:45-17:15
              除外後: Mo,Tu,We,Th,Fr 08:45-17:15; PH off
```

耳鼻いんこう科1件だけが `00:45-17:15`（他科は `08:45-17:15`）と入力されており、
施設全体の値を汚染していました。

### 日跨ぎの扱い

終了が開始より前の区間は日跨ぎ（当直帯）として採用します。ただし継続時間が**18時間**を
超えるものは夜勤ではなく打ち間違いとみなします。

根拠は継続時間の分布です。15〜16時間に188件が集中する一方（`17:00-08:30` 型の当直帯）、
20時間超の11件はいずれも終了が開始の直前にある誤入力でした。

```
15:30-15:00  霞ヶ浦医療センター 整形外科
13:00-12:00  南札幌病院 リハビリテーション科
18:30-17:00  浜松医科大学附属病院 リハビリテーション科
```

この基準で262件中250件を救済し、12件を除外に残しました。

### 24時間営業の表記

日跨ぎのマージ結果が24時間以上になると開始と終了が同じ表記になり、`08:30-08:30` という
**ゼロ長とも24時間とも読める曖昧な値**が出ます。この場合は `00:00-24:00` に正規化します。

### 曜日フラグと時刻の矛盾

全業態で22,195件（施設票の曜日フラグと、時刻の有無が食い違う）。性質の異なる2種類が
混在しており、一律にどちらを優先することはできません。

**A: フラグは休みなのに時刻がある（6,168件）**

時刻の中身で判断します。その時刻が「フラグが営業日と明示している曜日」の時刻と同一なら、
記入者が全曜日に同じ値を入れた一律入力とみなしてフラグを採ります。

| 性質 | 判断 | 件数 |
|---|---|---:|
| 営業日と同一時刻 | フラグを採用（曜日を落とす） | 3,874 |
| 独自の時刻 | 時刻を採用（現状維持） | 2,294 |

土曜に平日と同じ `09:00-17:00` が入っているのは一律入力と見るのが自然です。実際の
土曜診療なら午前のみが普通で、それは独自時刻の側に現れます。

```
市立旭川病院    土曜が平日と同一 → 落とした
札幌鈴木病院    Sa 09:30-12:30（平日は09:00-17:00）→ 残した
```

比較対象を「営業日」に限るのは、平日自身が休診指定されている場合に自分と比較して
常に一致してしまうのを避けるためです。

**B: フラグは営業日なのに時刻がない（16,027件）**

これは矛盾ではなく**時刻の記入漏れ**で、休みを意味しません。`opening_hours` には
「開いているが時刻不明」を表す構文が無いため、その曜日を書かなければ休みと誤解されます。
誤情報を出さないよう、**施設単位で出力を見送ります**。

判断内容は全件 `<業態>_conflicts.csv` の「採用した判断」列に残ります。

### 例外ルールの合成

**定期週**は部分パターンのみ採用します。第1〜5週すべて休みの指定は「毎週その曜日は休み」と
同義で、時刻の有無に既に反映されているためです。

**その他の休診日**は自由記述から日付を抽出します。区切り文字・桁揃え・スラッシュ表記・
範囲表現の揺れに対応し、94.3%から日付が取れます。

1本の範囲が**31日**を超える場合は終点の誤入力とみなし、原文を備考に残して採用しません。
判定は「合計日数」ではなく「1本の範囲の長さ」に対して行います。個別日付の羅列は
何日あっても正当だからです。

**日付を特定できない期間**（`GW` `お盆` `年末年始` `創立記念日` `夏季`）は
fallback ルールのコメントとして残します。

```
... ; Dec 29-Jan 03 off || off "GWは休診"
```

`||` の後ろに置くことが必須です。通常ルールとして書くと全時間帯を上書きし、
**平日まで休診判定になります**。参照実装で確認した結果:

- `...; "GWは休診"` … 平常日（水）が **閉** ❌
- `...; "GW" off` … 平常日（水）が **閉** ❌
- fallback separator の後ろに置いた形 … 平常日（水）が **開** ✅

```
Mo,Tu,We,Th,Fr 09:00-17:00; PH off || off "GWは休診"
```

### 救急科の分離

救急科（コード `09010`）は24時間・深夜運用が正常です。外来の `opening_hours` からは
分離し、誤りではなく性質の異なるデータとして `<業態>_emergency.csv` へ退避します。

当初これを外れ値として扱っており、外れ値の最大供給源（15%）になっていました。

## healthcare:speciality

### 対応表

126コードすべてに対応付けています（exact 73 / broader 53 / 未対応 0）。名称は523種と
揺れるので、対応付けはコードを鍵にします。

`mapping/speciality_mapping.csv` の「対応の確度」列:

- `exact` … OSM側に対応する値がある
- `broader` … 対応する値が無く上位概念に丸めた。情報が粗くなる
- `none` … 対応付けできず出力しない

同じコードが業態で別の意味を持つため、**業態別の上書き**を持てます。「業態」列が空の行が
既定で、業態名の入った行がその業態でのみ優先されます。

値はOSM wikiの文書化値を優先し、文書に無いが実運用で定着している値は出典を明記して
使い分けます（`dentistry` taginfo 1,518件、`dialysis` 483件）。

### 255文字の上限

OSMのタグ値は255文字が上限です。診療科をすべて列挙すると大学病院クラスで500文字を
超えるため、**上限を超えた施設だけ**段階的に短縮します。

| 段階 | 施設数 | 内容 |
|---|---:|---|
| 短縮なし | 6,612 | 完全な精度を保つ |
| 畳む | 706 | 細分値を上位科へ（`mapping/speciality_rollup.csv`） |
| `general` 単独 | 397 | 畳んでも収まらない場合 |

3段目はwikiの `general` が「General practitioner or **general hospital**」と定義されている
ことに依ります。31診療科を持つ病院はまさに総合病院で、語彙の趣旨に合致します。
畳む前の全値は備考に保存しています。

数字は病院の例です。診療所は畳み30件・`general` 1件、歯科診療所は畳み1件のみでした。

## 名称

### 運営主体の除去

「最後のトークンを施設名とする」規則は**採用しません**。病院では97.9%成立しますが、
助産所では25.9%まで落ちるためです（[data.md](data.md) 参照）。

代わりに**運営主体と識別できるトークンだけを先頭から取り除き、識別できなければ何も
削りません**。判定は3つの対応表に分かれます。

| ファイル | 役割 |
|---|---|
| `name_entity_prefixes.csv` | 法人格39種。長い順に照合する |
| `name_entity_suffixes.csv` | 法人名の接尾辞（`会` `組合` `厚生連` 等） |
| `name_facility_words.csv` | 施設種別語（`病院` `薬局` `相談室` 等） |

長い順の照合は必須です。短いパターンが先に当たると
`特定医療法人社団慶愛会…` が `特定医療法人` で止まり `社団` が施設名側に残ります。

3つ目の規則が効きます。**先頭が施設種別語で終わらず、末尾が終わる**場合だけ運営主体と
みなすので、危険な例が保護されます。

```
医療法人社団明日佳　札幌明日佳病院 → 札幌明日佳病院    先頭が施設種別語でない
三戸町国民健康保険　三戸中央病院   → 三戸中央病院
ふじい薬局　明野調剤             → ふじい薬局 明野調剤  先頭が薬局で終わる
オアシス　ファーマシー           → オアシス ファーマシー 末尾が施設種別語でない
```

トークンを落とした結果、先頭に再び法人格が現れることがあるため（`医療法人社団温光会
医療法人内藤病院`）、除去処理は収束するまで繰り返します。

### タグの割り当て

| タグ | 内容 | 件数 |
|---|---|---:|
| `name` | 運営主体を除いた施設名 | 206,043 |
| `official_name` | 元の正式名称（法人格を含む完全名） | 206,043 |
| `short_name` | 略称 | 業態による |
| `name:ja-Hira` | フリガナをひらがな変換 | 158,358 |
| `name:ja-Latn` | 音写のうち読みと一致を確認できたもの | 79,122 |
| `name:en` | 英語と判別できたもの | 83,552 |

`name:ja-Hira` はtaginfoで395,616件使われており、`name:ja_kana`（43件）ではなく
こちらが慣行です。

### 読みとの対応

フリガナは法人格を含む読みです（`カブシキガイシャアミヤヤッキョク`）。`name` から
運営主体を除いた施設では読みが対応しなくなるため、**`name:ja-Hira` を出力せず**
理由を備考に残します。

### name:ja-Latn の検証

音写をそのまま入れると「この名前のローマ字表記である」という主張が偽になる場合があります
（先頭が欠落、途中で切れている）。そこで**フリガナから独立にヘボン式ローマ字を導出して
突き合わせ、一致したものだけ採用**します。

| 判定 | 件数 | 比率 |
|---|---:|---:|
| 完全一致 | 71,340 | 82.9% |
| ほぼ一致（類似度0.9+） | 7,782 | 9.0% |
| 略記等（0.75+） | 3,455 | 4.0% |
| 不一致 | 3,451 | 4.0% |

比較時は長音（`ou`/`oo`/`uu`）、訓令式との揺れ（`sy`↔`sh`、`ti`↔`chi`）、連続文字を
畳んで吸収します。表記の流儀の違いで落とさないためです。

**出力には元の音写を使います。** 生成物は `Sapporoikadaigakufuzokubyouin` のように
語の区切りが無い続き綴りになるのに対し、元データは語間に空白があり読みやすいためです。

## 検証

### 独立した実装で確かめる

生成側（Python）と検証側を独立させ、自前の正規表現では気づけない誤りを拾います。
`opening_hours` はOSMの事実上の標準実装 `opening_hours.js` で全件を検証します。

この検証で実際に見つかった欠陥:

- 24時間営業が `08:30-08:30` となり、ゼロ長とも24時間とも読める曖昧な出力
- コメントを通常ルールとして書くと平日まで休診判定になる問題

### 検証器そのものを逆テストする

**何も検出しない検証器は無意味です。** 既知の不正な値（`tests/known_bad.csv`）を
かけて、狙った分類で検出されることを確かめます。

この逆テストで検証器自身の穴が見つかりました。コメントだけのルールは期間全体を
`unknown=true` の1区間で埋めるため、区間数を数えるだけの実装では破損を見逃していました。

### 偽陽性を避ける

「一定期間で一度も開かない」の判定は窓の取り方が難しく、2度修正しています。

- 1週間では「第1土曜のみ開院」が偽陽性になる
- 5週間でも「第2月曜のみ開院」が偽陽性になる。窓に入る唯一の第2月曜が**成人の日**
  （1月第2月曜）と重なり `PH off` で閉まるため

現在は5週間で高速に判定し、そこで引っかかった数件だけ13週間で再確認する2段階です。
全件を長い窓で走査すると数万件では時間がかかりすぎるためです。

### 現在の結果

全5業態206,043施設で、パースエラー・語彙エラー・タグ値長超過・値の重複はいずれもゼロです。
残る警告は日跨ぎが翌日ルールと衝突するもので、データが実際にそうなっている以上は
欠陥ではありません。既知の挙動として逆テストに固定してあります。
