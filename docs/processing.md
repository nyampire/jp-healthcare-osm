# 変換処理の設計と根拠

各判断の根拠を実データの数値とともに残します。
元データ側の性質は [data.md](data.md) を参照してください。

例はすべて実際の出力から採っており、`output/` の該当行と突き合わせて確認できます。

## 通しの例

慈啓会病院（ID `0111010000090`）を例に、入力から出力までを追います。
この施設は運営主体の除去、定期週、休診日、診療科の丸めのすべてを通ります。

施設票にはこう入っています。

```
正式名称     社会福祉法人　札幌慈啓会　慈啓会病院
フリガナ     シャカイフクシホウジン　サッポロジケイカイ　ジケイカイビョウイン
英語表記     Jikeikai Hospital
毎週フラグ   月=1 火=1 水=1 木=1 金=1 土=1 日=0
祝日に休診   0
定期週       第1,3,5週の土が休み（日は全週休み）
その他休診日  01月01日，01月02日，01月03日，12月30日，12月31日
```

診療科と診療時間の票には7診療科が並びます。

```
01001 内科           帯1 月=09:00-12:30  帯2 月=13:30-17:30  帯3 土=09:00-12:30
01020 消化器内科      帯1 月=09:00-12:30  帯2 月=13:30-17:00  帯3 土=09:00-12:30
01027 漢方内科        帯1 月=09:00-12:30  帯2 月=13:30-17:30
01028 老年内科        帯1 月=09:00-12:30  帯2 月=13:30-17:30  帯3 土=09:00-12:30
07001 精神科          帯1 月=09:00-12:30  帯2 月=13:30-17:30
09003 リハビリテーション科  帯1 月=09:00-12:30  帯2 月=13:30-17:00
09005 放射線診断科      帯1 月=09:00-12:30  帯2 月=13:30-17:30  帯3 土=09:00-12:30
```

これが次のタグになります。

```
name                  慈啓会病院
official_name         社会福祉法人　札幌慈啓会　慈啓会病院
short_name            慈啓会病院
name:en               Jikeikai Hospital
opening_hours         Mo,Tu,We,Th,Fr 09:00-12:30,13:30-17:30; Sa 09:00-12:30;
                      Sa[1,3,5] off; PH off; Dec 30-Jan 03 off
healthcare:speciality internal;gastroenterology;traditional_chinese_medicine;
                      geriatrics;psychiatry;physiatry;diagnostic_radiology
```

各段階で何が起きたかを追うと次のようになります。

月曜の終了時刻は診療科によって `17:00` と `17:30` に分かれますが、和集合を採るので
遅いほうの `17:30` が残ります。
土曜は帯3にだけ時刻があり、`Sa 09:00-12:30` として独立した規則になります。
定期週の第1,3,5週の土曜休みが `Sa[1,3,5] off` として土曜の規則を上書きします。
日曜は全週休みで、これは毎週フラグの `日=0` と同義なので規則を出しません。
`祝日に休診` が `0` なので `PH off` が付きます。
その他休診日の5日分は、年をまたぐ連続として `Dec 30-Jan 03` にまとまります。
漢方内科は OSM に対応値が無いため `traditional_chinese_medicine` に丸め、その事実を備考に残します。
名称は `社会福祉法人` と `札幌慈啓会` を運営主体として取り除きます。
フリガナは `シャカイフクシホウジン…` と運営主体を含むため `name` と対応せず、`name:ja-Hira` は出力しません。

## 通底する方針

元データの列は書き換えず、変換後の値は別列として持ちます。
判断を覆したくなったときに戻せることと、第三者が対比して検証できることを優先します。
上の例では `official_name` に元の正式名称がそのまま残っています。

判断を含む対応付けはスクリプトに埋め込まず、`mapping/` の CSV に外出しします。
医学的な判断や語彙の当てはめは、レビューして直せる形である必要があります。

除外や保留をした行は、理由とともに全件を一覧に残します。
除外して終わりにしません。

誤った値を出すより出力しません。
OSM では値を書かないコストは低い一方、誤った休診情報を書くと利用者が来院できなくなります。

判定基準は他行との比較ではなく絶対的な基準で行います。
理由が一意に定まり、除外リストから第三者が検証できるためです。
imports メーリングリストで説明とレビューを受ける以上、説明可能性を精度差より優先します。

最後の方針には経緯があります。
当初は中央値と最頻値による外れ値検出を実装しましたが、基準にした中央値そのものが
偏っている施設で正常値を誤検出しました。

```
伊勢崎佐波医師会病院 帯3 小児科  19:30-22:30  →  外れ値と誤判定
  同じコマの中央値は 00:00-08:30（当直枠）
```

夜間コマは母数が少なく、当直枠が中央値になるため、正当な夜間診療が弾かれていました。
絶対基準に切り替えた結果、除外は実データの0.45%まで減り、
最終出力が変わる施設は0.6%にとどまりました。

## opening_hours

### 組み立て

診療科と診療時間の票は1施設につき複数行を持ちますが、OSM の `opening_hours` は
ノードに1つしか持てません。
そこで曜日ごとに全診療科の区間を和集合して畳みます。

```
入力（月曜、7診療科ぶん）
  09:00-12:30, 13:30-17:30, 09:00-12:30, 13:30-17:00, 09:00-12:30, ...
和集合
  09:00-12:30, 13:30-17:30
月曜ぶんの規則（他の曜日と合成する前の中間結果）
  Mo 09:00-12:30,13:30-17:30
```

終了時刻が診療科によって `17:00` と `17:30` に分かれていますが、
和集合なので遅いほうが残ります。

そのうえで施設票の例外ルールを後ろに重ねます。
`opening_hours` は後ろのルールが前を上書きするため、順序が意味を持ちます。

```
基本時間 → 定期週の休み → 祝日 → 特定日の休み → 日付にできない期間のコメント

Mo,Tu,We,Th,Fr 09:00-12:30,13:30-17:30; Sa 09:00-12:30;
  Sa[1,3,5] off; PH off; Dec 30-Jan 03 off
```

`Sa 09:00-12:30` を先に置き、`Sa[1,3,5] off` を後に置くことで、
「土曜は午前診療、ただし第1,3,5土曜は休み」を表します。
順序を逆にすると土曜の休みが時間規則に上書きされて消えます。

### 除外の基準

和集合は最も早い開始と最も遅い終了を採るため、1行の誤入力が施設全体の値を汚染します。
これを防ぐため、外来として明らかに成立しない区間を除外してから畳みます。

| 分類 | 基準 | 件数 | 実例 |
|---|---|---:|---|
| `null_placeholder` | 開始と終了が同一 | 4,473 | `00:00-00:00` |
| `too_early` | 開始が06:00より前 | 2,413 | `00:45-17:15` |
| `too_late` | 終了が23:00より後 | 583 | `09:00-23:59` |
| `overnight_implausible` | 日跨ぎとしても18時間超 | 461 | `15:30-15:00` |
| `sentinel_24h` | `00:00-23:59` の定型 | 201 | 同左 |

全業態で8,131区間、対象の0.5%程度です。
実データを落とした分はさらに少なく、`null_placeholder` を除けば3,658件です。

汚染が是正された例を示します。

```
市立札幌病院
  除外前  Mo,We,Th,Fr 08:45-17:15; Tu 00:45-17:15
  除外後  Mo,Tu,We,Th,Fr 08:45-17:15; PH off
```

火曜だけ別扱いになっていた原因は、耳鼻いんこう科1件の `00:45-17:15` です。
他の26診療科はすべて `08:45-17:15` でした。
`08:45` の打ち間違いとみて `too_early` で除外し、火曜が他の曜日と同じ規則にまとまりました。

### 日跨ぎの扱い

終了が開始より前の区間は日跨ぎ（当直帯）として採用します。
ただし継続時間が18時間を超えるものは、夜勤ではなく打ち間違いとみなします。

根拠は継続時間の分布です。
15時間から16時間に188件が集中する一方、20時間超の11件はいずれも終了が開始の直前にありました。

```
採用する例（全業態で1,663区間）
  19:00-07:00   152件。夜から翌朝までの当直帯（12時間）
  18:00-09:00   104件（15時間）
  17:00-08:30    92件（15時間30分）

除外する例（全業態で461区間）
  19:00-13:00    39件（18時間）
  09:00-07:00    36件（22時間）
  15:30-15:00    霞ヶ浦医療センター 整形外科（23時間30分）
```

採用する側は夕方から夜に始まり翌朝に終わる形で、当直帯として筋が通ります。
除外する側は、朝に始まって翌朝まで続く形（`09:00-07:00`）や、
終了が開始の直前にある形（`15:30-15:00`）で、外来の時間として説明がつきません。
この基準で病院では262件中250件を救済し、12件を除外に残しました。

日跨ぎを採用した施設では、`opening_hours` に翌日へ渡る区間がそのまま出ます。

```
吉岡病院  Mo,Tu,We,Fr 09:00-12:30,15:00-17:30,18:00-08:30; Th 09:00-12:30,15:00-08:30
```

### 24時間営業の表記

日跨ぎのマージ結果が24時間以上になると、開始と終了が同じ表記になります。

```
08:30 開始、翌 08:30 終了  →  08:30-08:30
```

この表記はゼロ長とも24時間とも読めるため、`00:00-24:00` に正規化します。

```
同善病院  Mo,Tu,We,Th,Fr,Sa,Su,PH 00:00-24:00; Dec 30-Jan 03 off
```

### 曜日フラグと時刻の矛盾

全業態で22,195件あります。
性質の異なる2種類が混在しており、一律にどちらを優先することはできません。

A は「フラグは休みなのに時刻がある」ケースで6,168件です。
時刻の中身で判断します。
その時刻が、フラグが営業日と明示している曜日の時刻と同一なら、
記入者が全曜日に同じ値を入れた一律入力とみなしてフラグを採ります。

```
市立旭川病院    土曜 08:30-17:00（平日の最頻値と同一）  →  フラグを採用して土曜を落とす
札幌鈴木病院    土曜 09:30-12:30（平日は09:00-17:00）    →  時刻を採用して土曜を残す
```

前者の出力は `Mo,We,Fr 08:00-19:00; Tu,Th 08:00-17:00; PH off; Dec 30-Jan 04 off` となり、
土曜の規則が消えています。

土曜に平日と同じ時刻が入っているのは一律入力と見るのが自然です。
実際の土曜診療なら午前のみが普通で、それは独自時刻の側に現れます。

| 性質 | 判断 | 件数 |
|---|---|---:|
| 営業日と同一時刻 | フラグを採用（曜日を落とす） | 3,874 |
| 独自の時刻 | 時刻を採用（現状維持） | 2,294 |

比較対象を営業日に限るのは、平日自身が休診指定されている場合に、
自分と比較して常に一致してしまうのを避けるためです。

B は「フラグは営業日なのに時刻がない」ケースで16,027件です。
これは矛盾ではなく時刻の記入漏れで、休みを意味しません。

`opening_hours` には「開いているが時刻不明」を表す構文が無いため、
その曜日を書かなければ休みと誤解されます。
誤情報を出さないよう、施設単位で出力を見送ります。

```
桑園中央病院
  フラグ  月から金が営業日
  時刻    月火水木のみ。金曜が空
  出力    opening_hours を出力しない
  備考    曜日フラグが営業日とする金曜の時刻が無く、書くと休診と誤解されるため
```

金曜を落として `Mo,Tu,We,Th …` と書くこともできますが、それは金曜が休みだという
主張になります。
フラグは営業日と言っているので、その主張は誤りです。

判断内容は全件が `<業態>_conflicts.csv` の「採用した判断」列に残ります。

### 例外ルールの合成

定期週は部分パターンのみ採用します。

```
採用する    土=第1,3,5週が休み  →  Sa[1,3,5] off
採用しない  日=第1週から第5週すべて休み  →  毎週フラグの 日=0 と同義なので出力しない
```

第1週から第5週すべて休みの指定は「毎週その曜日は休み」と同義で、
時刻の有無に既に反映されているためです。

その他の休診日は自由記述から日付を抽出します。
区切り文字、桁揃え、スラッシュ表記、範囲表現の揺れに対応し、94.3%から日付が取れます。

```
01月01日，01月02日，01月03日，12月30日，12月31日  →  Dec 30-Jan 03
年末年始（12月29日～1月3日）                      →  Dec 29-Jan 03
12/29~1/3                                     →  Dec 29-Jan 03
```

年をまたぐ連続は1本の範囲にまとめます。

1本の範囲が31日を超える場合は、終点の誤入力とみなして採用せず、原文を備考に残します。

```
8/14-5/16（改行）12/29-1/3
  →  Dec 29-Jan 03 だけを採用
  →  備考に [31日超の範囲:8/14-5/16] を残す
```

判定は合計日数ではなく1本の範囲の長さに対して行います。
個別日付の羅列は何日あっても正当だからです。
実際に60日分の個別日付を並べている施設があり、それは正しい入力です。

日付を特定できない期間（`GW`、`お盆`、`年末年始`、`創立記念日`、`夏季`）は、
fallback ルールのコメントとして残します。

`||` の後ろに置くことが必須です。
通常ルールとして書くと全時間帯を上書きし、平日まで休診判定になります。
参照実装で 2026年1月14日（水）の状態を確かめた結果は次のとおりです。

```
Mo,Tu,We,Th,Fr 09:00-17:00; "GWは休診"           水曜が閉になる
Mo,Tu,We,Th,Fr 09:00-17:00; "GW" off             水曜が閉になる
Mo,Tu,We,Th,Fr 09:00-17:00; PH off || off "GWは休診"   水曜は開のまま
```

### 救急科の分離

救急科（コード `09010`）は24時間と深夜の運用が正常です。
外来の `opening_hours` からは分離し、誤りではなく性質の異なるデータとして
`<業態>_emergency.csv` へ退避します。

```
天使病院  救急科  月 帯1  00:00-12:00
天使病院  救急科  火 帯1  00:00-12:00
```

この `00:00-12:00` を外来と混ぜると、施設全体の開始時刻が `00:00` に引きずられます。
当初これを外れ値として扱っており、外れ値の最大の供給源（15%）になっていました。

## healthcare:speciality

### 対応表

126コードすべてに対応付けています（exact 73、broader 53、未対応 0）。
名称は523種と揺れるので、対応付けはコードを鍵にします。

`mapping/speciality_mapping.csv` の実際の行を示します。

```
業態      コード  診療科目名        OSM値                          確度      備考
(既定)    09003  リハビリテーション科  physiatry                     exact    wikiの定義が該当
(既定)    01027  漢方内科         traditional_chinese_medicine  broader  漢方は中医学と同一ではない
(既定)    02022  乳腺外科         surgery                       broader  対応値が無い。973施設と多く要検討
dental   08991  インプラント       dentistry                     broader  歯科では口腔外科ではない
```

「対応の確度」列は3値です。
`exact` は OSM 側に対応する値があるもの、`broader` は対応する値が無く上位概念に丸めたもの、
`none` は対応付けできず出力しないものです。
`broader` の行には、なぜ丸めたかを備考に書いています。

最後の行のように、同じコードが業態で別の意味を持つ場合は業態別の上書きを持てます。
「業態」列が空の行が既定で、業態名の入った行がその業態でのみ優先されます。

値は OSM wiki の文書化値を優先します。
文書に無いが実運用で定着している値は、出典を明記して使い分けます
（`dentistry` は taginfo 1,518件、`dialysis` は483件）。

### 255文字の上限

OSM のタグ値は255文字が上限です。
診療科をすべて列挙すると大学病院クラスで500文字を超えるため、
上限を超えた施設だけ段階的に短縮します。

```
段階1 短縮なし（6,612施設）
  慈啓会病院  internal;gastroenterology;traditional_chinese_medicine;geriatrics;
             psychiatry;physiatry;diagnostic_radiology        108文字

段階2 畳む（706施設）
  札幌医科大学附属病院  27値では255文字を超えるため細分値を上位科へ畳んで22値
                    internal;neurology;pulmonology;cardiology;...  248文字

段階3 general 単独（397施設）
  市立札幌病院  畳んでも収まらないため general の1語のみ            7文字
              畳む前の31値は備考に保存
```

段階3は wiki の `general` が「General practitioner or general hospital」と
定義されていることに依ります。
31診療科を持つ病院は総合病院にあたり、語彙の趣旨に合致します。

数字は病院の例です。
診療所は畳み30件と `general` 1件、歯科診療所は畳み1件のみでした。

## 名称

### 運営主体の除去

「最後のトークンを施設名とする」規則は採用しません。
病院では97.9%成立しますが、助産所では25.9%まで落ちるためです（[data.md](data.md) 参照）。

代わりに、運営主体と識別できるトークンだけを先頭から取り除き、識別できなければ何も削りません。
判定は3つの対応表に分かれます。

| ファイル | 役割 | 例 |
|---|---|---|
| `name_entity_prefixes.csv` | 法人格39種。長い順に照合する | `医療法人社団`、`社会福祉法人` |
| `name_entity_suffixes.csv` | 法人名の接尾辞 | `会`、`組合`、`厚生連` |
| `name_facility_words.csv` | 施設種別語 | `病院`、`薬局`、`相談室` |

長い順の照合は必須です。

```
特定医療法人社団慶愛会札幌花園病院
  短い順に当てた場合  特定医療法人 で止まり → 社団慶愛会札幌花園病院（社団が残る）
  長い順に当てた場合  特定医療法人社団 が当たり → 慶愛会札幌花園病院
```

3つ目の規則が効きます。
先頭が施設種別語で終わらず、末尾が終わる場合だけ運営主体とみなすので、危険な例が保護されます。

```
医療法人社団明日佳　札幌明日佳病院  → 札幌明日佳病院      明日佳は施設種別語で終わらない
三戸町国民健康保険　三戸中央病院    → 三戸中央病院        保険は施設種別語で終わらない
ふじい薬局　明野調剤              → ふじい薬局 明野調剤   先頭が薬局で終わるので削らない
オアシス　ファーマシー            → オアシス ファーマシー  末尾が施設種別語でないので削らない
```

トークンを落とした結果、先頭に再び法人格が現れることがあります。

```
医療法人社団温光会　医療法人内藤病院
  1回目  温光会 が接尾辞に当たり除去 → 医療法人内藤病院
  2回目  医療法人 が法人格に当たり除去 → 内藤病院
```

そのため除去処理は収束するまで繰り返します。

### タグの割り当て

| タグ | 内容 | 件数 |
|---|---|---:|
| `name` | 運営主体を除いた施設名 | 206,043 |
| `official_name` | 元の正式名称（法人格を含む完全名） | 206,043 |
| `short_name` | 略称 | 業態による |
| `name:ja-Hira` | フリガナをひらがな変換 | 158,358 |
| `name:ja-Latn` | 音写のうち読みと一致を確認できたもの | 79,122 |
| `name:en` | 英語と判別できたもの | 83,552 |

`name:ja-Hira` は taginfo で395,616件使われており、`name:ja_kana`（43件）ではなく
こちらが慣行です。

### 読みとの対応

フリガナは法人格を含む読みです。

```
名称     株式会社アミヤ薬局
フリガナ  カブシキガイシャアミヤヤッキョク
name    アミヤ薬局
```

`name` から運営主体を除いた施設では読みが対応しなくなるため、
`name:ja-Hira` を出力せず理由を備考に残します。
上の例で `かぶしきがいしゃあみややっきょく` を出すと、`name` の読みとして偽になります。

### name:ja-Latn の検証

音写をそのまま入れると、この名前のローマ字表記であるという主張が偽になる場合があります。

```
名称=旭川脳神経外科循環器内科病院   音写=Asahikawa Noge        途中で切れている
名称=医療福祉センター札幌あゆみの園  音写=sapporoayuminosono    先頭が欠落
```

そこでフリガナから独立にヘボン式ローマ字を導出して突き合わせ、一致したものだけ採用します。

```
採用する例
  name=長生会病院      読み=ちょうせいかいびょういん     音写=Chouseikai Byouin
  name=自衛隊札幌病院   読み=じえいたいさっぽろびょういん   音写=Jieitai Sapporo Byoin

採用しない例
  name=札幌厚生病院    音写=Sapporo Kousei Byoin   読みは運営主体を含み対応しない
```

| 判定 | 件数 | 比率 |
|---|---:|---:|
| 完全一致 | 71,340 | 82.9% |
| ほぼ一致（類似度0.9以上） | 7,782 | 9.0% |
| 略記など（0.75以上） | 3,455 | 4.0% |
| 不一致 | 3,451 | 4.0% |

比較時は長音（`ou`、`oo`、`uu`）、訓令式との揺れ（`sy` と `sh`、`ti` と `chi`）、
連続文字を畳んで吸収します。
表記の流儀の違いで落とさないためです。

出力には元の音写を使います。
導出したローマ字は `Sapporoikadaigakufuzokubyouin` のように語の区切りが無い続き綴りになるのに対し、
元データは `Sapporo Medical University Hospital` のように語間に空白があり読みやすいためです。

## 検証

### 独立した実装で確かめる

生成側（Python）と検証側を独立させ、自前の正規表現では気づけない誤りを拾います。
`opening_hours` は OSM の事実上の標準実装 `opening_hours.js` で全件を検証します。

この検証で実際に見つかった欠陥は2つあります。

```
08:30-08:30 という出力  ゼロ長とも24時間とも読める曖昧な値だった
コメントの置き場所      通常ルールとして書いており平日まで休診判定になっていた
```

### 検証器そのものを逆テストする

何も検出しない検証器は無意味です。
既知の不正な値をかけて、狙った分類で検出されることを確かめます。
`tests/known_bad.csv` に7件のフィクスチャを固定しています。

```
正常な値                    検出されないのが正しい
コメントを通常ルールに誤配置    never_open として検出されるべき
ゼロ長区間                  zero_span として検出されるべき
構文エラー                  error として検出されるべき
第1土曜のみ開院              検出されないのが正しい（偽陽性の確認）
正しいコメント配置            検出されないのが正しい
日跨ぎの当直帯               warning が出るのが既知の挙動
```

この逆テストで検証器自身の穴が見つかりました。
コメントだけのルールは期間全体を `unknown=true` の1区間で埋めるため、
区間数を数えるだけの実装では破損を見逃していました。
確実に開いている区間だけを数えるよう直しています。

### 偽陽性を避ける

「一定期間で一度も開かない」の判定は窓の取り方が難しく、2度修正しています。

```
窓が1週間   Sa 09:00-12:00; Sa[2,3,4,5] off
            第1土曜のみ開院する施設。窓に第1土曜が入らず偽陽性

窓が5週間   Mo 13:30-14:30; Mo[1,3,4,5] off; PH off
            第2月曜のみ開院する施設。窓に入る唯一の第2月曜が
            成人の日（1月の第2月曜）と重なり PH off で閉まるため偽陽性
```

現在は5週間で高速に判定し、そこで引っかかった数件だけ13週間で再確認する2段階です。
全件を長い窓で走査すると、数万件では時間がかかりすぎます。

### 現在の結果

全5業態206,043施設で、パースエラー、語彙エラー、タグ値長超過、値の重複はいずれもゼロです。
残る警告は日跨ぎが翌日ルールと衝突するもので、データが実際にそうなっている以上は欠陥ではありません。
既知の挙動として逆テストに固定しています。
