# 到達点と、インポート前に決めること

このリポジトリは変換までを扱います。
ここには、どこまで出せているかと、OSM へ投入する前に決める必要がある論点を置きます。

数値は `output/` を生成した時点のもので、パイプラインを変えれば動きます。
最新の値は `npm run all` の標準出力と `output/reports/*_validation.csv` に出ます。

捨てた元データの座標は `備考` に書くので、作業者が値を見て判断できます。
1kmの規則、県外の規則、穴埋めの規則で捨てた405件が対象です。

除外した9,363件の内訳は、地番方式の住所が5,187件、位置レベルが足りないものが4,176件です。

逆テストはすべて通ります（`npm run selftest`）。

## OSM へのインポートについて

実際に OSM へ投入する場合は
[Import Guidelines](https://wiki.openstreetmap.org/wiki/JA:Import/Guidelines) に従ってください。

合意で決めるべき項目が4つあります。

`ref` 系のタグをどのキーで持つか決まっていません。
医療情報ネットの ID を保持できると更新への追随や重複の判定に使えますが、
キーの命名は勝手に決められません。

診療所の `amenity` が暫定です。
病床数が空欄の31,399件を無床とみなして `doctors` に寄せており、72,962件が推定に該当します。
一律 `clinic` にする案もあります。

番地を `推定` で付けた行は出力しません。
町字までは台帳で住居表示実施済みと分かっていますが、番地は入力文字列を機械的に切ったもので、
住居表示台帳と突き合わせられた8,219件のうち番地が実在したのは33.9%でした。
街区符号が100を超える545件は正解が0件です。
判定と根拠は [processing.md](processing.md) の「推定を台帳と突き合わせた」にまとめています。

`healthcare:speciality` に対応値が無い診療科があります。
心療内科は `psychiatry` に、乳腺外科は `surgery` に丸めています。
論点は [speciality-mapping.md](speciality-mapping.md) の末尾にまとめています。

## データ側で残っている課題

課題が4つあります。

座標が `0.0, 0.0` の16,243件のうち、9,266件は補完していません。
これに、元データが穴埋めに入れた座標を捨てて住所からも補えなかった97件が加わり、座標を持たない施設は9,363件です。
5,187件は地番方式の住所です。
地番のデータを参照して得た座標はライセンス上出力できないため、補完の対象から外しています。
残る4,176件は位置レベルが3以下で、建物から数百メートルずれるため採用していません。

`推定` の番地28,120件を出力していません。
住居表示台帳と突き合わせられた8,219件のうち、番地が実在したのは33.9%でした。
施設と `addr:full` は残るので情報は失われません。
外した番地を残余に出すかは決めていません。残余はいま建物名や階を入れる場所です。
詳細は [processing.md](processing.md) の「推定を台帳と突き合わせた」にあります。

`note` に住所の未解釈部分が66,251件残っています。
うち18,684件は数字で始まり、住居表示を実施していない町字で地番が残ったものが多くを占めます。
残りは建物名や階や部屋番号で、`addr:housename` や `addr:floor` に移せる可能性があります。
投入前に分割の方針を決める必要があります。

ジオコーディングで位置レベル8に届かない原因が未解明です。
参照データの有無では説明できない事例が残っています。
